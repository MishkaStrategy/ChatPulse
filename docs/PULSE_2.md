# Pulse 2.0

Pulse 2.0 — отдельный автономный режим ChatPulse для длинной работы, где после заданного числа автоответов текущий чат заменяется новым чатом того же ChatGPT Project.

## Изоляция от Pulse 1.0

Pulse 2.0 не использует список чатов, master-stop, task mode, счётчики или scheduler Pulse 1.0.

- UI: отдельная extension-вкладка `pulse2/pulse2.html`.
- Storage: `chatpulse2State`.
- Scheduler: `chatpulse-pulse2-monitor` и `chatpulse-pulse2-capture`.
- Runtime channel: `chatpulse-pulse2` Port.
- Рабочая вкладка: отдельная фоновая вкладка Chrome.
- Pulse 1.0 продолжает работать через прежний `service-worker-v2.js`; `service-worker-v3.js` только загружает оба независимых engine.

Для защиты от двойной отправки Pulse 2.0 не запускается на чате, который уже активен в работающем Pulse 1.0. Если Pulse 1.0 позднее активируется на текущем чате Pulse 2.0, Pulse 2.0 останавливается с ошибкой до следующей отправки.

## Настройки

- **Текущий чат** — исходная ссылка `/c/...`; после ротации автоматически заменяется новым URL.
- **Проект ChatGPT** — ссылка project page, куда режим возвращается для создания следующего чата.
- **Текст автоответа** — обычное сообщение продолжения, по умолчанию `go`.
- **Стартовое сообщение нового чата** — первое сообщение нового project chat; пустое значение наследует текст автоответа.
- **Задержка автоответа** — время стабильности завершённого ответа до очередной отправки.
- **Автоответов на цикл** — сколько обычных автоответов отправить в одном чате до ротации.
- **Количество циклов** — сколько чатов всего обработать, включая исходный чат как цикл №1.

Стартовое сообщение нового чата не считается обычным автоответом цикла.

## Цикл

1. Pulse 2.0 открывает исходный чат в собственной фоновой вкладке.
2. Первый увиденный завершённый ответ становится baseline.
3. После неизменного ответа ассистента в течение заданной задержки Pulse 2.0 отправляет автоответ ровно один раз этому ответу.
4. После достижения лимита автоответов режим не бросает генерацию: он ждёт завершённый ответ на последний автоответ и только после его стабильности начинает ротацию.
5. Вкладка переходит по ссылке проекта; helper подготавливает composer нового project chat.
6. Pulse 2.0 отправляет стартовое сообщение.
7. Начинается обязательная задержка **2 минуты**. Затем URL вкладки должен стать постоянной ссылкой `/c/...`.
8. Если URL ещё не готов, Pulse 2.0 повторяет захват каждые 30 секунд, максимум 10 попыток. Он не угадывает conversation ID.
9. После успешного захвата новый URL становится `currentChatUrl`, счётчик автоответов обнуляется и начинается следующий цикл.
10. После последнего заданного цикла Pulse 2.0 завершает работу без создания лишнего чата.

## Failure policy

Pulse 2.0 действует fail-closed в операциях, способных отправить сообщение не в тот чат: неверная project URL, потеря авторизации, невозможность подготовить новый project chat, конфликт с Pulse 1.0 и невозможность получить новый постоянный `/c/...` не приводят к догадкам или бесконечной ротации.

Transient ошибки обычной проверки текущего чата сохраняются в runtime и повторяются на следующем scheduler tick без сброса счётчиков.
