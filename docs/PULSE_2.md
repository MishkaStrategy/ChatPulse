# Pulse 2.0

Pulse 2.0 — отдельный автономный режим ChatPulse для длинной работы по нескольким ChatGPT Projects. Каждый проект работает как независимый маршрут со своей фоновой вкладкой, текущим чатом, фазой и счётчиками циклов.

## Изоляция от Pulse 1.0

Pulse 2.0 не использует список чатов, master-stop, task mode, счётчики или scheduler Pulse 1.0.

- UI: отдельная extension-вкладка `pulse2/pulse2.html`.
- Storage: `chatpulse2State`, schema v2.
- Scheduler: `chatpulse-pulse2-monitor` и `chatpulse-pulse2-capture`.
- Runtime channel: `chatpulse-pulse2` Port.
- Рабочие вкладки: по отдельной managed-вкладке на каждый активный маршрут; обычный мониторинг может идти в фоне, но создание нового project chat временно переводит соответствующую вкладку на передний план.
- Pulse 1.0 продолжает работать через `service-worker-v2.js`; `service-worker-v3.js` загружает оба независимых engine.

Один и тот же чат одновременно в Pulse 1.0 и Pulse 2.0 использовать нельзя. Также один `/c/...` URL нельзя назначить двум маршрутам Pulse 2.0.

## Несколько проектов

В интерфейсе Pulse 2.0 можно добавлять до 20 проектных маршрутов. Для каждого задаются:

- название маршрута;
- **Проект ChatGPT** — обязательная ссылка project page;
- **Текущий чат** — необязательная ссылка `/c/...`.

Общие для всех маршрутов настройки:

- текст автоответа;
- стартовое сообщение нового чата;
- задержка автоответа;
- число обычных автоответов на цикл;
- число циклов на каждый проект.

Маршруты ведут runtime независимо: ошибка одного проекта переводит в ошибку только этот маршрут и не останавливает остальные.

## Старт без текущего чата

Поле **Текущий чат** можно оставить пустым. В этом случае при запуске Pulse 2.0:

1. открывает configured project page этого маршрута;
2. создаёт новый project chat;
3. отправляет стартовое сообщение;
4. ждёт обязательные 2 минуты;
5. захватывает реальный постоянный `/c/...` URL;
6. сохраняет его как текущий чат маршрута;
7. продолжает этот чат как **цикл №1**.

Первый автоматически созданный чат не считается ротацией в цикл №2. Его стартовое сообщение также не увеличивает счётчик обычных автоответов.

## Защита редактируемых настроек

UI хранит отдельный draft настроек. Live state updates из background обновляют статус и runtime, но не перезаписывают поля, которые пользователь редактирует и ещё не сохранил. Это устраняет мигание/сброс формы при фоновых state push.

## Фоновый мониторинг и ночная работа

После того как первый project chat создан и его постоянный URL сохранён, маршрут переходит в `monitoring`. Реальный ChatGPT может замораживать или не полностью обновлять DOM фоновой вкладки, поэтому due-проверка маршрута работает так:

1. Pulse запоминает вкладку, которой пользователь пользовался до проверки;
2. временно активирует managed chat-вкладку и ждёт короткую отрисовку;
3. читает состояние ответа и при необходимости отправляет автоответ;
4. если ротация не началась, возвращает пользователя на предыдущую вкладку, но только если пользователь сам не успел переключиться куда-то ещё.

Внутренний monitor alarm просыпается каждые 30 секунд, но это **не означает автоответ каждые 30 секунд**. Проверяются только маршруты, у которых наступил `nextCheckAt`. После обнаружения нового завершённого ответа запускается именно настроенная задержка автоответа. Например, при задержке 1 час `go` отправляется после часа стабильности конкретного ответа, а не через дополнительный час только из-за редкого опроса.

После отправки сообщения и после захвата нового project chat Pulse делает короткие 30-секундные проверки, чтобы быстро заметить следующий ответ ассистента и начать отсчёт его заданной задержки.

Важно: как локальное Chrome-расширение ChatPulse не может выполнять проверки, пока сам Chrome или компьютер полностью спит/выключен. После пробуждения Chrome alarm продолжит работу, но прошедшее время сна не превращается в реально выполненные фоновые действия.

## Обычный цикл маршрута

1. Pulse 2.0 наблюдает текущий чат маршрута.
2. Первый завершённый ответ становится baseline.
3. После неизменного ответа ассистента в течение заданной задержки отправляется автоответ ровно один раз этому ответу.
4. После достижения лимита автоответов Pulse ждёт завершённый ответ на последний автоответ.
5. Маршрут переходит в свой проект, создаёт следующий чат и отправляет стартовое сообщение.
6. После двухминутной задержки Pulse захватывает реальный `/c/...` URL. Если URL ещё не готов, проверка повторяется каждые 30 секунд, максимум 10 попыток.
7. Новый URL становится текущим, per-cycle счётчик обнуляется и начинается следующий цикл.
8. После последнего заданного цикла конкретный маршрут завершается без создания лишнего чата.
9. Когда завершены все маршруты, Pulse 2.0 выключается.

## Переключение на Project-вкладку при создании чата

ChatGPT может не полностью гидратировать composer и связанные элементы в фоновой вкладке Chrome. Поэтому при создании первого или следующего project chat Pulse 2.0 не оставляет Project-вкладку фоновой:

1. делает managed-вкладку маршрута активной;
2. по возможности фокусирует окно Chrome, в котором она находится;
3. ждёт завершения загрузки страницы;
4. только после этого ищет project composer и отправляет стартовое сообщение.

Обычные проверки уже существующего текущего чата по-прежнему могут выполняться в фоне. Принудительное переключение вкладки ограничено фазой `rotating`, то есть именно моментом создания нового чата.

## Восстановление создания чата

Фаза создания первого/следующего чата имеет отдельный recovery-watchdog. Пока маршрут находится в `rotating`, Chrome alarm будит background engine каждые 30 секунд. Это нужно для Manifest V3 service worker: если он был выгружен после Start или во время долгой загрузки проекта, сохранённый маршрут не остаётся навсегда в состоянии **создание чата**, а продолжает работу автоматически.

Повторный recovery не перезагружает уже открытый project page без необходимости. Если стартовое сообщение уже было отправлено и managed tab успел получить новый постоянный `/c/...` URL до прерывания background, Pulse принимает этот URL как созданный чат и переходит к обычному двухминутному capture-процессу вместо создания второго чата.

## Failure policy

Pulse 2.0 действует fail-closed в операциях, способных отправить сообщение не в тот чат: неверная project URL, потеря авторизации, невозможность подготовить новый project chat, конфликт URL и невозможность получить новый постоянный `/c/...` не приводят к догадкам или бесконечной ротации.

Background operations сериализованы общей очередью, поэтому независимые маршруты не могут перезаписать runtime друг друга при одновременных alarm/UI событиях.
